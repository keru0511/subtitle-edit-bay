# 編集時間短縮ロードマップ

この文書は、編集画面で素材を探す時間と、字幕・ハイライトを整える時間を段階的に短縮するための実装順を固定する。各項目は独立した変更としてレビューできるようにし、依存する機能を先に完成させる。

## 目的

- 文字起こし結果を確認し、修正し、再利用するまでの往復を短くする
- 長尺動画から短尺候補を作る判断を、ローカル処理と明示的なユーザー操作で支援する
- AIや外部サービスが利用できない場合も、既存の手動ワークフローを壊さない
- プロジェクト、素材、生成物を上書きや不透明な自動変更から保護する

## 実装順

### 1. 文字起こし・字幕レビュー基盤

1. #182 字幕レビューキュー
2. #183 用語辞書候補
3. #184 字幕の一括編集
4. #185 音声自動ミックス・ダッキング
5. #186 処理キューと再開
6. #187 チャンネル・話者プリセット
7. #188 字幕・タイムラインの書き出し

この層では、編集対象と設定をデータとして安定させる。レビュー中の字幕、辞書候補、一括変更は、常に差分確認と取り消し可能性を持たせる。書き出しは最後に行い、編集用データを直接破壊しない。

### 2. Codex連携

1. #169 app-server stdio クライアント
2. #170 編集提案スキーマと原子的適用
3. #171 GUIバックエンドセッション
4. #172 Codex編集UI
5. #173 配布・診断・E2E・ドキュメント
6. #168 Codex連携Epicの完了判定

Codexは編集を直接確定せず、対象範囲、変更理由、期待するrevisionを含む編集提案を返す。GUIは提案をプレビューし、検証後に一括適用する。プロジェクト全体や認証情報、素材ファイルを外部へ送らない。

### 3. ハイライト候補

1. #175 ローカル候補生成
2. #176 候補一覧UI
3. #177 Codexによる再順位付け
4. #178 ユーザー選択からの嗜好学習
5. #179 映像シグナル
6. #174 ハイライトEpicの完了判定

候補生成はローカル処理を標準とし、再順位付けや映像シグナルは機能フラグと実行時間上限を持つ。候補の重複、同一場面への偏り、説明できない順位変更を避ける。

### 4. 公開・復旧・マルチソース

1. #189 YouTube投稿用パッケージ
2. #190 スナップショットと復旧
3. #191 複数素材の短尺編集
4. #193 Windowsランチャーと配布
5. #194 GUIアップデーター

公開用パッケージは投稿情報とサムネイル候補をローカル出力するだけで、アップロードやアカウント操作を行わない。復旧機能を先に確認したうえで複数素材と配布・更新を追加する。

## 共通の受け入れ条件

- 既存プロジェクトを開いたときに新しい任意項目がなくても動作する
- 入力、設定、生成物の境界が明確で、素材を勝手に移動・上書きしない
- 上書きが必要な操作は明示確認を要求し、キャンセル時に元データを変更しない
- 外部プロセスにはタイムアウト、キャンセル、終了コード確認を適用する
- 主要な正常系、競合、異常入力、非ASCIIパスを自動テストまたは固定fixtureで確認する
- ローカル処理を無効化した場合のフォールバックと、機能フラグの既定値を文書化する
- PRには対象Issue、変更範囲、確認手順、未実施の確認を記載する

## リリースゲート

### Gate A: 編集データ

- 字幕レビュー、辞書、一括編集、音声、キュー、プリセット、書き出しのCIが成功している
- SRT/VTT/CSVとタイムラインJSONのround-trip fixtureが壊れていない
- 既存プロジェクトの読み込みと、明示的な上書き確認が固定されている
- 判定対象はCIの `windows-tests` と `ffmpeg6-compat`。対象テストは `test_subtitle_*`、`test_transcription_*`、`test_audio_*`、`test_processing_queue.py`、`test_channel_presets.py`、`test_subtitle_export.py` とし、変更PRでは該当テスト名を説明に記載する
- 必須fixture/artifactは、既存プロジェクトJSON、字幕のSRT/VTT/CSV、タイムラインJSON、処理キューJSON、および各fixtureから再生成した出力のfingerprint。CIログにround-trip結果と上書きキャンセル結果を残し、差分があればゲートを失敗させる

### Gate B: 支援機能

- Codex連携とハイライト候補が、機能無効・タイムアウト・キャンセル時も編集を壊さない
- 外部へ送るデータ範囲とログの秘匿方針がテストと文書に反映されている
- 候補の採用、却下、修正がユーザー操作で完結し、理由を追跡できる
- 判定対象は `windows-tests` のCodex・ハイライト関連テスト。固定fixtureは字幕本文、候補ID、ランキング応答、フィードバックJSON、キャンセル/タイムアウト結果とし、ログartifactには本文・絶対パス・認証情報が含まれないことを確認する
- 外部Codexを使うテストは実サービスを呼ばず、固定RPC応答または機能無効経路を使用する。機能無効、承認拒否、タイムアウト、キャンセルの各結果をCIログに残し、編集データのrevisionが変わらないことをartifactとして保存する

### Gate C: 配布と復旧

- 投稿パッケージ、スナップショット、複数素材のfixtureが成功している
- Windowsのクリーン環境で起動、更新、更新失敗からの復旧を確認できる
- 更新前後のバージョン、checksum、ログ、ロールバック結果を追跡できる
- 判定対象は `release.yml` の `test`、`build`、`publish` と `ci.yml` の `windows-installer-smoke`。配布artifactは `SubtitleEditBay-Setup.exe` と同名の `.sha256`、検証fixtureは投稿パッケージJSON、スナップショット、複数素材プロジェクトとする
- ロールバックは「エラーを記録した」だけでは合格にしない。旧版のインストーラーまたは旧版ディレクトリの完全なsnapshotを更新開始前に保持し、更新途中の失敗を注入した後に、旧版の `VERSION`、主要ファイル、checksumが実際に復元され、旧版アプリが起動することを `windows-installer-smoke` または同等のWindows固定テストで確認する
- 更新前後のバージョン、入力/出力checksum、snapshotの場所、復元結果を1つのCIログartifactにまとめ、復元できなかった場合はGate Cを失敗させる

## 計測

- 動画選択から編集可能になるまでの時間
- 文字起こし完了から最初の採用字幕までの時間
- 1本の動画から候補を採用して書き出すまでの操作数
- 手動修正された候補と却下された候補の割合
- キャンセル、競合、復旧、更新失敗の件数

指標は個人を評価するためではなく、機能追加による実編集時間と失敗復旧時間の変化を比較するために使う。
