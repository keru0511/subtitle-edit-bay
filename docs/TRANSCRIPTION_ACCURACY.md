# 初回文字起こしの認識設定

初回の文字起こしで誤生成を抑えるため、GUI・Craig・通常動画・バッチの共通コマンドを `src.whisperx_runner` に接続しています。認識はWhisperXのPython APIで一度実行し、その結果を同じ音声に対して語単位で時刻合わせします。字幕の事後検出・文字列削除・再認識は行いません。

## 設定と狙い

| 設定 | 変更前 | 変更後 | 狙いと注意点 |
| --- | --- | --- | --- |
| 候補探索数 `beam_size` | 5 | 10 | 初回生成で探索する候補を増やす。処理時間は増加する可能性がある。 |
| 反復ペナルティ `repetition_penalty` | 1.0 | 1.2 | 生成時に繰り返したトークンの確率を下げる。自然な繰り返しにも影響しうる。 |
| 反復禁止 `no_repeat_ngram_size` | 0 | 0 | 実際の反復発言を禁止しない。 |
| 音声のまとめ単位 `chunk_size` | 30秒 | 15秒 | 一度に認識・時刻合わせする区間を短くする。文脈の減少による誤認識も比較対象。 |
| 発話開始 `vad_onset` の既定値 | 0.35 | 0.5 | WhisperX標準値に揃え、弱い雑音を発話として採用しにくくする。小声の取りこぼしに注意。 |
| 発話終了 `vad_offset` の既定値 | 0.2 | 0.363 | WhisperX標準値に揃える。語尾の取りこぼしに注意。 |

`large-v3`、日本語指定、CPU/GPU・計算精度の選択は既存設定を引き継ぎます。VAD値を既存の設定ファイルや引数で明示している場合は、その値を尊重します。新しいVAD値を既存環境へ適用する場合は `shared.vad_onset` を `0.5`、`shared.vad_offset` を `0.363` に設定します。

生成設定の正本は `src/transcription_profile.py` です。`condition_on_previous_text=False` は従来どおり維持します。語単位の時刻合わせ自体は従来から存在しており、新規の同期補正ではありません。時刻合わせには元音声とWhisperXが返す絶対時刻をそのまま渡します。動画と別録音の全体オフセットや録音時間の伸縮は、この変更では修正しません。

## WhisperX 3.8.6での実効性

[固定バージョンのASR実装](https://github.com/m-bain/whisperX/blob/v3.8.6/whisperx/asr.py)では、`beam_size` と `repetition_penalty` は生成器に渡されます。一方、このバッチ経路は `no_speech_threshold` や `compression_ratio_threshold` による判定を実施しないため、その値を追加しただけでは誤生成対策になりません。

[固定バージョンのCLI](https://github.com/m-bain/whisperX/blob/v3.8.6/whisperx/__main__.py)は反復ペナルティを受け取れないため、公開Python APIを使う実行入口を用意しています。[時刻合わせ](https://github.com/m-bain/whisperX/blob/v3.8.6/whisperx/alignment.py)は言語に対応した既定モデルを使用します。

## キャッシュ

辞書の有無にかかわらず、認識設定・WhisperXバージョン・音声の絶対パスとサイズと更新日時・文脈フィンガープリントが一致する結果だけ再利用します。旧形式のキャッシュは次回実行時に一度作り直します。処理が失敗した場合は成功メタデータを残しません。既に編集・保存したプロジェクトの字幕は自動で再生成しません。

## 実行と検証

```sh
python -m src.transcribe run --input sample.mkv --audio-track 0:a:0 --output-dir out/accuracy --run
python -m unittest tests.test_whisperx_runner tests.test_transcription_execution
```

単体テストでは生成設定の受け渡し、1回だけの認識実行、元音声・絶対時刻での時刻合わせ、無音結果、話者分離、キャッシュの更新を検証します。モデル推論はモックです。

反復ペナルティ1.2は、提供されたゲーム実況の音源と公開固定録音を用いて実モデルで比較した候補です。ゲーム実況の正解文は人手未注釈のため、誤挿入・脱落の改善率は未測定です。固定録音では文字誤り・挿入・脱落・区間逸脱は0でした。調整対象の音源では自然な反復も起こり得るため、生成結果を機械的に削除しません。公開実録音によるCI比較は別節の手順で実施し、実際のゲーム実況に対する効果とは区別します。

## CIでの実認識比較

[実音声による文字起こしCI](TRANSCRIPTION_ACCURACY_CI.md) で、公開の日本語実録音を使った旧版との比較を実行します。設定の受け渡しだけでなく、実モデルの認識JSONを評価対象にします。テスト素材の範囲と実際のゲーム実況の問題は区別してください。

## 無音を文字の持続時間に含めないCTC時刻合わせ

WhisperX 3.8.6の[時刻合わせ](https://github.com/m-bain/whisperX/blob/v3.8.6/whisperx/alignment.py)では、文字を出力しないblankフレームも直前の文字の経路に含めて集約します。複数の発話を含む区間では、語末が長い無音をまたいで次の発話まで伸びることがあります。

初回認識プロファイルv2以降は、文字とblankを別状態として扱うCTC経路を使用します。文字とblankの滞在、次状態への移動、異なる文字へのblankを飛ばす移動を比較し、最大尤度の経路を選びます。同じ文字の連続にはblankを経由させ、自然な繰り返しを保持します。文字の開始・終了と信頼度の集約には非blankフレームだけを使用します。全探索と一致することを小さな確率行列で検証します。

文字起こしモデルの認識区間・生成設定・本文・元音声を維持し、同じアラインメントモデルの1回の出力から時刻を計算します。音声の再認識、モデルの再推論、評価用の正解時刻による切り詰めは行いません。認識キャッシュには`alignment_backend=ctc-blank-v1`を含め、以前の時刻結果を再利用しません。

実装はNumPyのCTC経路計算を、専用CLIプロセス内のWhisperX `backtrack`へ時刻合わせの間だけ適用します。通常終了・例外の両方で元に戻し、このアダプター経由の呼び出しはロックで直列化します。WhisperX 3.8.6の内部インターフェースに依存するため、ランタイム更新時は実音声CIの互換性確認が必要です。単語境界の人手正解との差はまだ評価しておらず、CTCのフレーム境界を厳密な音韻境界とみなすものではありません。

## 認識後の字幕生成で本文を失わない

認識JSONに本文が残っていても、字幕のページ分割と描画の幅が異なると、描画時に一部が「…」へ省略されることがありました。また、文字幅の合計が2行の容量以内でも、自然な改行候補の偏りによって省略が起きる場合がありました。

自動ページ分割では描画と同じ幅を使い、実際の整形で本文が残ることも確認します。収まらない単位は語時刻を使って次ページへ送り、長い単位も先に分割します。短い断片の結合・長い表示時間の分割を済ませてから、最終的な本文保持を確認します。認識モデル・認識本文は変更しません。

既に保存済みのページや手動編集の行数・改行指定は、その場で一律に再分割しません。この修正を適用するには元の認識JSONから自動ページを生成し直してください。これは字幕表示の欠落修正であり、聞き違いや元音声との時刻誤差の改善を証明するものではありません。

## プロファイルv3の反復調整

ゲーム実況では発言していない語句の挿入を重く見る方針に合わせ、初回認識の `repetition_penalty` を1.1から1.2へ上げます。後から反復文字を削除する処理は追加しません。 `no_repeat_ngram_size=0` を維持し、発言した反復を一律には禁止しません。設定変更によりプロファイルをv3へ更新し、旧認識結果のキャッシュは再利用しません。

ローカルのlarge-v3・CPU int8で、提供された実況音声の計12分を同じ入力WAVで比較したところ、93:53付近の「いい」の連続は6文字から1文字になりました。85分台の「怖い」の反復は7回から5回、正規化後の全文は2,789文字から2,763文字に変わりました。短い2区間だけの試行では、1.2は1.3に比べて周辺本文を多く保持しました。実際の発言について人手の正解注釈はなく、これらの減少を誤認識の改善数とはみなしません。提供動画と認識JSONは公開リポジトリやCIへ追加しません。

公開固定録音120秒のローカル実認識では、1.2の正規化後CER、挿入、脱落、区間逸脱、語時刻欠損はすべて0でした。使用OSはmacOS ARM64で、Windows CIと同じ環境ではありません。CIは従来の旧版・新版2ジョブ並列比較を維持し、新しい推論ジョブを増やしません。モデル取得と実行時間のばらつきがあるため、この値から性能向上や処理速度の改善は断定しません。
