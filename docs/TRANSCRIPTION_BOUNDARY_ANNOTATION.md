# 実録音の単語境界を評価する

既存の発話区間からの逸脱検査に加え、`word_annotation` のある録音では人手で付けた開始・終了時刻と比較します。発話区間内に収まるずれや、語尾が途中で切れる問題を検出するための指標です。

**現在の公開固定素材には人手の単語境界注釈がありません。** 評価器の追加と実録音の精度検証は別です。レポートの `not_annotated` は未検証を表し、誤差ゼロ・合格を意味しません。単体テストの人工的な時刻も、実録音の正解ラベルとしては扱いません。

## 正解データの作り方

1. 問題を含む短い区間を、前後の発話が欠けないように切り出します。推奨は1件10〜20秒程度です。笑い声、早口、自然な小声、複数話者、ゲーム音など、実際に含まれる条件を記録します。音量を下げただけの素材を「自然な小声」と呼ばないようにします。
2. 元音声を聞いて全文を転記し、波形と再生で各単語の開始・終了を確認します。自然な反復や言いよどみは削除しません。字幕の見た目に合わせて時刻を付けません。
3. 記録する時刻は切り出したファイルの先頭を0秒とします。配置先の `clip.start` は採点時に加算されます。音声を時間伸縮した場合は元の注釈を流用できません。
4. 配布元の人手注釈を使う場合は固定版と注釈IDを記録します。自分で注釈した場合は担当者・確認日・切り出し位置を `source` に記録します。WhisperXや別のASR、自動字幕から作った時刻を人手正解と扱わないでください。
5. 公開CIに収録する音声は再配布条件を確認し、出典・ライセンス・SHA-256を記録します。提供された動画URLだけではリポジトリへの再配布許可とみなしません。未確認の音源はローカルに置きます。

`manifest.json` の対象 `clips` に次の形の情報を加えます。以下は**形式を説明する例**で、実録音の注釈ではありません。

```json
{
  "text": "はいはい進みます",
  "start": 12,
  "duration": 3,
  "word_annotation": {
    "method": "human",
    "source": "注釈担当者・確認日・元音源と切り出し位置、または配布元の固定注釈ID",
    "words": [
      {"text": "はいはい", "start": 0.2, "end": 0.8},
      {"text": "進みます", "start": 1.1, "end": 2.5}
    ]
  }
}
```

本文・単語を既存の正規化（全半角・句読点・空白）で揃えた後、単語の連結が全文と一致することを必須とします。時刻の逆転・重なり・音声範囲外は拒否します。同等表記の置換範囲を複数の単語に分割する注釈も拒否します。重なった話者を一本の直列の単語列として注釈する形式ではありません。同時発話の正解には話者ごとの評価設計が別途必要です。

`limits.word_boundary_tolerance_seconds` も指定します。例として0.2秒を使えますが、採用する値はモデル出力を見る前に字幕用途に合わせて決め、悪い結果を通すために緩めないでください。既存の発話区間用の0.4秒とは独立です。

## 採点と失敗条件

- 正解文と認識文を文字単位で照合し、人手注釈の単語に対応する文字群の最初・最後の時刻を比較します。日本語の文字単位の `words` と、複数文字の語を同じ方法で扱います。
- 開始と終了それぞれの絶対誤差の平均、最大境界誤差、許容誤差を超える単語数、終了が早すぎる単語数を記録します。平均だけで合否を決めません。1語でも境界の許容値を超えれば失敗します。
- 単語内に誤認識・脱落・挿入がある場合や、対応文字の時刻がない場合は `unmatched_words` に数え、失敗させます。評価できた単語だけの良い平均で通しません。
- 注釈がある録音数／全録音数、正解単語数／照合できた単語数も出します。未注釈の録音について単語精度の保証はできません。
- 人手注釈の正しさ自体はJSONから証明できません。出典と実際の聴取・確認が必要です。

## モデルを動かさず再採点する

人手注釈を追加・修正するとき、音声と認識結果が変わっていなければ再推論は不要です。

```sh
python scripts/benchmark_transcription.py \
  --score-transcript /path/to/recognition.json \
  --manifest /path/to/manifest.json \
  --output /path/to/boundary-report
```

`report.json` に単語別の正解／実際の時刻と誤差、認識JSONのSHA-256を保存し、`report.md` に概要を出します。絶対基準を満たさなければ終了コード1です。このモードはモデルや音声ファイルを読み込まず、指定JSONと指定正解の採点だけを行います。元音声との対応・推論条件・旧版からの改善は証明しません。

新旧の実認識比較は従来の `--baseline-root` / `--candidate-root` を使います。単語採点は既存の推論結果へ適用するため、モデル読み込みやCIジョブは増えません。新しい実録音を加える場合の推論時間増加は別途測定します。
