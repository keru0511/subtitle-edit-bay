# UIテスト見直し（初回）

## 追記：カットの復元と全解除

カットタイムラインの既存範囲を実クリックして選択し、「このカットを復元」からUndoする。カットされていない位置をクリックして選択を解除し、開始・終了時刻を実キー入力して「選択範囲を復元」で既存カットの一部だけが戻ることを確認する。最後に「全解除」→Undo→Redo→画面上部の保存を行い、保存前後のプロジェクトファイルも照合する。このケースをWindows CIにも追加する。

## 追記：シーケンスの削除と履歴

シーケンスのクリップカードにある「削除」を実クリックし、画面のUndo／Redoで削除と復元を確認する。保存前のファイルは変わらず、保存後は削除結果がプロジェクトファイルに残ることを確認する。このケースをWindows CIにも追加する。

クリップの開始・終了時刻をEnterなしで入力して画面上部から保存し、両方の時刻が保存されることを確認する。クリップカードの音声連動、ミュート、音量スライダー、音声位置補正、後続クリップの切り替え方法と時間も実操作し、プロジェクトファイルまで照合する。これら３ケースをWindows CIにも追加する。

## 追記：音声ミキサーの操作と保存

通常画面の音量設定でも、トラックのミュート→保存→リセット→再保存を画面から操作し、保存ファイルと照合する。「音声プレビューを作り直す」ではキャッシュが再生成され、プロジェクトファイルや未保存状態を変更しないことを確認する。このケースもWindows CIで実行する。

音声トラックを画面で有効化して保存した後、処理中はリセットできず、処理終了後にリセットして再保存できることを実クリックとプロジェクトファイルで確認する。再生可能な音声素材を使い、「プレビューを作り直す」がキャッシュを再生成し、保存ファイルを変更せず、画面の5秒進む・戻る・スライダー移動・再生・一時停止が再生成後も動くことを確認する。両ケースをWindows CIでも実行する。

ミキサーを開いた直後に5秒進む操作をしても、初期位置の復元タイマーが後から再生位置を0秒へ戻すことを再現した。手動の位置移動と再生開始で初期位置の復元を終了し、再生メディアの長さとシーク可否が判明するまでは操作ボタンを無効にする。復元タイマーが動いている状態での位置移動と再生の進行をGUIテストで確認する。

## 追記：書き出し直前の出力先選択とショート入力の確定

通常動画の「出力先を選択」ボタンを実クリックし、選択を中止した場合はプロジェクトと保存ファイルを変更せず、選択した場合は元のプロジェクト保存場所を保ったまま指定フォルダへ書き出しを開始することを確認する。画面の「出力先」ボタンから開くフォルダも照合する。

ショート動画では、クリップ時刻やBGM開始時刻を入力して Enter を押さずに書き出すと、入力前の値が保存される問題を再現した。書き出し前に入力欄の編集を確定する。通常動画編集へ戻る場合も、同じ問題でクリップ時刻が失われるため、画面を閉じる前に確定する。実キー入力とクリック後の保存ファイルを照合する４ケースをWindows CIにも追加する。

追加確認では、クリップ時刻と背景色を空欄にしたまま書き出すと、画面の入力は未完成でも以前の値で処理が始まる問題を再現した。クリック後のフォーカスだけを調べる方法はLinuxとWindowsで取りこぼしたため、未完成の設定がある間は書き出しと画面退出のボタンを無効にし、理由を画面に表示する。背景色の入力後に別の操作へ移った場合も検証し、値を完成させた後に再試行できる３ケースをWindows CIへ追加する。

BGM開始時刻または背景色を入力した直後に音量を操作すると、設定画面の再描画で入力が消える問題も再現した。利用者が編集した欄は再描画中も保持し、書き出し・通常編集へ戻る前に設定へ反映する。音量操作と保存ファイルまでの２ケースをWindows CIへ追加する。

クリップ時刻を入力した直後に「下へ移動」を押すと、入力がクリップへ反映されずに消えることも確認した。並べ替え・削除・表示方法変更・追加の前に編集中の時刻を確定し、未完成の時刻がある間はこれらの操作を受け付けない。入力後の並べ替え、別クリップの削除、未完成入力からの再試行、設定変更後の保存、未完成入力を残した設定変更と再試行を実操作と保存ファイルで確認する５ケースをWindows CIへ追加する。

未完成のクリップ時刻から別の入力欄へフォーカスを移すと、空欄が元の時刻に戻り、書き出し・画面退出も再び可能になる問題を再現した。編集途中の値をフォーカス移動後も表示し、完成するまで書き出しと退出を止める。入力を完成させた後の保存ファイルまで確認するケースをWindows CIへ追加する。

20件のクリップを末尾までスクロールして先頭へ戻る間も、未完成の時刻を表示し続け、書き出しと退出を止める。値を完成させて保存できることをWindows CIでも確認する。

文字起こし辞書の使用スイッチは、画面で切り替えて保存・再表示したときの状態と設定ファイルへの反映を確認する。処理中は同じスイッチを無効化する。辞書の読み込みと文字起こしへの適用は既存の単体テストで確認する。

素材ファイルのドロップは、バックエンドの分類・処理中の拒否テストに加え、画面全体のドロップ領域へQtのドラッグ開始・ドロップイベントを送り、素材への反映と処理中の領域無効化を確認する。

シーケンスタイムラインでは、素材を既存クリップの前へ置く操作と末尾の右側へ置く操作を実ドラッグで検証する。末尾へのドロップも最後のクリップの前へ挿入される問題を修正し、タイムライン全体のドロップ領域に覆われて到達しないクリップ個別のドロップ領域を削除した。このケースをWindows CIでも実行する。

## 追記：処理中の字幕編集

通常・拡大字幕編集について、処理中は追加・削除・履歴・入力欄・タイムライン編集を使えず、処理終了後に再び操作できることをGUIテストで固定した。無効な追加ボタンを実クリックしても字幕が増えないことも確認する。画面以外から字幕編集APIを呼んだ場合も、プロジェクト・履歴・未保存状態・保存ファイルが変わらないことを検証する。対象は字幕編集であり、他の編集モードの操作可否は別途確認する。

セルフレビューで、入力中に処理状態へ移ると未確定の字幕本文や時刻が失われる経路を確認した。本文と時刻の下書きを字幕IDに結び付けて保持し、画面切り替え、字幕選択、一覧のスクロールによって入力欄が再生成されても処理終了後に保存できることをGUIテストで固定する。処理中の保存は拒否し、未確定の入力がある状態ではウィンドウを閉じない。

追加確認では、スクロールバーの実ドラッグ、処理中の拡大画面の分割操作、書き出しと文字起こしを始める直前の時刻入力もGUIテストで検証する。

再監査では、字幕タイムラインの実ドラッグがバックエンド直接呼び出しのテストだけでは確認できていないと分かった。通常画面の共通タイムラインで、処理中は字幕の移動と両端の伸縮が反映されず、終了後は反映されることをマウス操作で検証する。このテストで、伸縮ハンドルのドラッグを親のスクロール領域が奪い、終了時刻が保存されない問題を再現したため、ハンドルが操作を保持するよう修正した。終了時刻の入力途中での処理開始、処理中の話者色変更、既存の未保存編集がある状態でのウィンドウ終了も検証する。

自動保存の確認では、処理開始後もタイマーが動き、手動保存の拒否を迂回して保存できる状態を再現した。処理開始時にタイマーを止め、遅れて届く自動保存要求も処理中は拒否し、終了後に未保存の変更があれば再開することを検証する。このケースもWindows CIで実行する。

他モードの確認を進め、カットと音量について、処理中は画面の変更ボタンが使えず、画面外から編集APIを呼んでもプロジェクト・履歴・保存ファイルが変わらず、終了後は同じ画面から編集を再開できることをGUIテストで固定した。両ケースはWindows CIでも実行する。シーケンスの既存テストは、再読込後の編集欄が実際に表示されていることを確認してから無効化を検証するようにした。クリップ欄は親の編集領域によって処理中に無効化される。

ショート編集の見どころ候補では、動画処理中に「もう一度探す」を押すと再解析は拒否される一方、既存候補だけ消える経路を確認した。再試行前に処理中・プロジェクト未読込を判定し、候補の追加・除外・除外取消も処理中は画面とAPIの両方で拒否する。候補・プロジェクト・保存ファイルが維持され、処理終了後は候補除外を再開できることをGUIテストで固定し、Windows CIでも実行する。

文字起こし辞書では、処理中に保存ボタンを無効化しても保存ショートカットとEscが残り、設定保存APIからは処理中でも設定ファイルを書き換えられた。辞書画面で未確定の入力を持ったまま処理中へ移った場合は保存・戻る・ウィンドウ終了を拒否し、処理終了後に入力を保存できることをGUIテストで固定した。通常時も、辞書入力中のウィンドウ終了で下書きを設定ファイルへ保存する。保存失敗時はウィンドウを残して再試行でき、設定保存に失敗した場合は文字起こし・書き出し処理を開始しない。これらのケースはWindows CIでも実行する。

## 優先して対応したい点

### 1. 拡大字幕編集の入力直後の保存・書き出し

macOSのオフスクリーンGUIテストで、文章を編集して保存・書き出しをクリックしても、保存内容が編集前のままになる。変更前でも次の3ケースが再現した。

- `test_project_save_restart_reload_e2e_preserves_edits_and_unsaved_switch`
- `test_qml_multiline_editor_live_previews_and_saves_manual_break`
- `test_editor_render_e2e_saves_edits_and_burns_subtitles`

`MainWorkflowScreen.qml` の拡大字幕入力はフォーカスを失う際に本文をバックエンドへ反映する。保存ボタンは直接 `saveProject()` を呼ぶ。フォーカス移動に依存する確定順序が原因候補。テストは実クリックを使うが、入力自体は `setProperty("text", ...)` であるため、実キー入力およびWindows実画面での再現範囲は未確認。

次は入力確定と保存・書き出しの順序を検証する。テスト側で事前に別コントロールへフォーカスを移して成功させるだけの修正はしない。

### 2. 一時ディレクトリのパス比較がmacOSの表記差で失敗する

`/var/...` と解決後の `/private/var/...` を直接比較しているため、同じファイルでも既存ケースが失敗する。代表例は `test_changing_export_directory_preserves_editor_and_autosave_path`。次は共有GUIテストセッションの一時ルートを正規化するか、ファイル同一性を検証する比較へ整理する。画面に表示するパスの契約とは分けて扱う。

`test_output_unset_qml_offers_export_and_distinct_save_locations` はパス比較失敗後にポップアップの後処理を飛ばし、後続のショート画面検索にも失敗する。失敗時の後処理も確認する。

### 3. 字幕操作のボタン接続に検証の空白があった

削除・履歴操作にはバックエンド直接呼び出しのテストがあるが、通常編集画面のボタンから一連の結果を確認する検証が不足していた。今回、既存GUIテストモジュールに以下を追加した。

- 最後の字幕を削除 → 操作可否更新 → Undo → Redo → 保存 → 再読込
- Undo後に別の字幕を追加 → 古いRedoが無効になる
- 保存失敗 → 元ファイル・未保存編集の保持 → 同じ保存ボタンで再試行
- 再生位置が字幕の端・範囲外では分割不可 → 中央で分割 → Undo

いずれも対象ボタンを実クリックし、操作本体をモックしない。保存失敗の注入と、このケースの自動保存タイマー開始だけをモックする。再読込と再生位置設定はバックエンドAPIを利用する。
