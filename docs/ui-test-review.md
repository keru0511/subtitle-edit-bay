# UIテスト見直し（初回）

## 追記：処理中の字幕編集

通常・拡大字幕編集について、処理中は追加・削除・履歴・入力欄・タイムライン編集を使えず、処理終了後に再び操作できることをGUIテストで固定した。無効な追加ボタンを実クリックしても字幕が増えないことも確認する。画面以外から字幕編集APIを呼んだ場合も、プロジェクト・履歴・未保存状態・保存ファイルが変わらないことを検証する。対象は字幕編集であり、他の編集モードの操作可否は別途確認する。

セルフレビューで、入力中に処理状態へ移ると未確定の字幕本文や時刻が失われる経路を確認した。本文と時刻の下書きを字幕IDに結び付けて保持し、画面切り替え、字幕選択、一覧のスクロールによって入力欄が再生成されても処理終了後に保存できることをGUIテストで固定する。処理中の保存は拒否し、未確定の入力がある状態ではウィンドウを閉じない。

追加確認では、スクロールバーの実ドラッグ、処理中の拡大画面の分割操作、書き出しと文字起こしを始める直前の時刻入力もGUIテストで検証する。

再監査では、字幕タイムラインの実ドラッグがバックエンド直接呼び出しのテストだけでは確認できていないと分かった。通常画面の共通タイムラインで、処理中は字幕の移動と両端の伸縮が反映されず、終了後は反映されることをマウス操作で検証する。このテストで、伸縮ハンドルのドラッグを親のスクロール領域が奪い、終了時刻が保存されない問題を再現したため、ハンドルが操作を保持するよう修正した。終了時刻の入力途中での処理開始、処理中の話者色変更、既存の未保存編集がある状態でのウィンドウ終了も検証する。

自動保存の確認では、処理開始後もタイマーが動き、手動保存の拒否を迂回して保存できる状態を再現した。処理開始時にタイマーを止め、遅れて届く自動保存要求も処理中は拒否し、終了後に未保存の変更があれば再開することを検証する。このケースもWindows CIで実行する。

他モードの確認を進め、カットと音量について、処理中は画面の変更ボタンが使えず、画面外から編集APIを呼んでもプロジェクト・履歴・保存ファイルが変わらず、終了後は同じ画面から編集を再開できることをGUIテストで固定した。両ケースはWindows CIでも実行する。シーケンスの既存テストは、再読込後の編集欄が実際に表示されていることを確認してから無効化を検証するようにした。クリップ欄は親の編集領域によって処理中に無効化される。

ショート編集の見どころ候補では、動画処理中に「もう一度探す」を押すと再解析は拒否される一方、既存候補だけ消える経路を確認した。再試行前に処理中・プロジェクト未読込を判定し、候補の追加・除外・除外取消も処理中は画面とAPIの両方で拒否する。候補・プロジェクト・保存ファイルが維持され、処理終了後は候補除外を再開できることをGUIテストで固定し、Windows CIでも実行する。

文字起こし辞書では、処理中に保存ボタンを無効化しても保存ショートカットとEscが残り、設定保存APIからは処理中でも設定ファイルを書き換えられた。辞書画面で未確定の入力を持ったまま処理中へ移った場合は保存・戻る・ウィンドウ終了を拒否し、処理終了後に入力を保存できることをGUIテストで固定した。通常時も、辞書入力中のウィンドウ終了で下書きを設定ファイルへ保存する。保存失敗時はウィンドウを残して再試行でき、設定保存に失敗した場合は文字起こし・書き出し処理を開始しない。これらのケースはWindows CIでも実行する。

素材再指定では、処理中は画面の再指定ボタンが無効でも、バックエンドを直接呼ぶとプロジェクトの動画・音声参照を変更できた。再指定APIと設定画面の終了を処理中は拒否し、既存プロジェクト・保存ファイルを維持する。処理終了後は同じ画面で再指定し、画面を閉じられることをGUIテストで固定してWindows CIでも実行する。

AI編集案の適用では、字幕案と音量案の適用ボタン・APIが処理中の変更を拒否していなかった。処理中は提案を保持し、プロジェクト・履歴・保存ファイルを変えず、終了後に音量案を適用できることをGUIテストで固定した。提案一覧の行番号がQML内で未定義となる警告も修正し、チェックボックスによる選択と適用ボタンの有効状態を実クリックで検証する。このケースもWindows CIで実行する。

ショート編集の初期化APIは、他のショート編集操作と異なり処理中でもクリップ一覧を生成し、履歴と未保存状態を変更できた。ショート編集の共通確定経路で処理中の変更を拒否し、初期化前後のプロジェクト・履歴・保存ファイルと処理終了後の再実行をGUI回帰テストで固定する。このケースもWindows CIで実行する。

設定画面の数値欄は、入力途中で空欄にしたまま保存すると `Number("")` により `0` として扱われた。数値が未確定の間は画面の保存ボタンを無効化し、別の保存・処理開始経路からも非有限値を設定ファイルへ書き込まない。実キー操作での空欄、保存拒否時の設定・ファイル保持、再入力後の保存成功をGUI回帰テストで固定し、Windows CIでも実行する。

日本語入力では、Qtの合成入力イベントを使い、変換中の文字がまだ保存されず、確定イベント後の日本語本文が通常・拡大字幕画面から保存できることをGUIテストで確認する。両ケースをWindows CIでも実行する。合成イベントはOSのIMEによる保存クリック時の確定動作を再現しないため、Windows実機での変換中クリック操作は引き続き未検証とする。

文字起こし結果の「追加・統合」は、従来のGUIテストでは選択ダイアログの表示までで、ボタンから結果保存までの接続を確認していなかった。時刻入力直後に追加ボタンを押し、既存字幕の時刻と本文を保持しつつ新しい字幕を統合する一連の操作を、模擬処理の完了と保存ファイルの再読込まで検証する。一時プロジェクトを本来の保存先と分け、処理後に削除することも確認する。「キャンセル」は処理を起動せず保存ファイルを変えない。両ケースをWindows CIでも実行する。

シーケンス編集の「動画を追加」は、従来の画面テストが素材追加APIを直接呼んでいた。既存の操作テストでボタンをクリックし、選択ダイアログから素材一覧へ登録されることを確認してから、クリップ追加とUndo／Redoを検証する。このケースもWindows CIで実行する。

素材設定の「音声のずれを自動調整」は、従来は文字起こしへの設定受け渡しを確認していたが、解析ボタンから選択トラックと手動補正値が渡る操作は未検証だった。ボタンの実クリックから解析完了表示まで確認するケースを追加し、Windows CIでも実行する。

追加監査では、Qt GUIの回帰テスト全体がLinuxでのみ実行されていたため、Windows CIでも処理中の本文・時刻の保持、一覧のスクロール、タイムラインの移動・両端の伸縮を実操作で確認する対象ケースを指定した。Windowsの既存テスト群と同じPythonプロセスではQtアプリケーションの単一インスタンス制約に当たるため、別のCIステップで実行する。入力途中で検証上は未確定となる時刻も、処理終了後に続きを入力して保存できることを確認する。

## 追記：入力直後の保存・書き出しの修正

以下の初回記録にある入力確定の問題は、通常編集・拡大編集の両方で実キー入力でも再現した。保存・書き出し・プレビュー更新の共通入口でIMEの確定を要求し、入力欄のフォーカス終了処理を完了してからバックエンドを呼ぶように修正した。拡大編集を閉じる前にも同じ入力確定を行う。

キー入力と実クリック／保存ショートカットを使う回帰テストを25件追加した。通常編集・拡大編集の保存と書き出し、ヘッダー保存、プレビュー更新、保存失敗後の再試行を対象とする。書き出しはプロセス開始時に保存済み本文を確認し、既存の実動画生成テストも併せて検証する。

追加レビューで、保存ショートカット後のフォーカス・選択範囲の喪失と、終了時の保存失敗を無視して閉じる問題を確認した。ショートカット保存後は入力欄と選択範囲を復元し、保存失敗時は終了を拒否する。成功・失敗後の入力継続、終了の再試行、プロジェクト未読込時の終了を回帰テストで検証する。

再レビューで、入力中の削除後に隣の字幕を上書きする問題、分割で旧本文が混ざる問題、Undo後の保存で未確定本文が再適用される問題を確認した。未確定本文の管理をプロジェクトパスと字幕IDで統一し、追加・削除・分割・Undo／Redoの前に同じ入力確定経路を通す。Undoは直前の本文編集を取り消し、Redoで復元できる。削除済みID・別プロジェクトへの入力は破棄する。プロジェクトを開く・別名保存の前にも確定する。拡大編集の行復元時はモデル更新後に選択を同期し、通知の再入を防ぐ。これらを9件の回帰テストで検証した。

追加確認では、拡大編集の並べ替えで選択行の循環更新警告が発生し、Windows性能テストでもスクロール先の本文編集後に元の選択行へ戻って後続の時刻・話者・サイズ変更が失敗した。ListViewの内部行番号からバックエンドへの逆同期を廃止し、本文入力の開始時に対象字幕を選択する。選択表示とスクロール追従はバックエンドの選択状態を使い、内部currentIndexによる本文欄からのフォーカス移動を防ぐ。並べ替え、3,000件の一覧をスクロールした後の実キー入力と連続編集、上下キーの境界操作を3ケースで検証する。

再起動後の再読込テストの子プロセスは、保存検証と無関係な外部AI接続を無効にし、一時プロジェクト内の設定で起動するようにした。保存・書き出しの内部コード文字列を要求する検査は実操作テストに置き換えた。

追加修正後の `tests.test_gui_editor`・`tests.test_qml_static`・`tests.test_production_integration` は計250ケースすべて成功。portableテストも1087ケースで失敗・エラーなし（Windows専用4ケースはスキップ）。Ruff、CIテスト分類検証、差分チェックも成功した。

検証ではmacOSの一時ディレクトリを `TMPDIR=/private/tmp` に指定する。初回記録のパス表記差の問題自体は今回の修正対象に含めない。Windows実機・日本語IMEの変換中操作は未検証。

最新mainの機能別窓口への分割を統合し、字幕操作は `subtitles`、書き出しは `workflow` 経由へ移行した。入力確定と選択同期の修正は維持し、動画処理のテスト差し替え先も更新した。統合後のGUI関連250ケース、3,000件・10,000件の性能シナリオ（各1回、再生2秒）の操作結果検査はすべて成功した。

拡大編集の話者欄は初期表示時しか選択を同期していなかったため、Undoでデータが戻っても旧話者を表示していた。話者と話者一覧の変更通知で選択を同期するよう修正した。実キー操作で話者変更→Undo／Redo→保存を2往復するケースと、話者一覧の並べ替えでも選択した話者を保つケースを追加した。

## 優先して対応したい点

### 1. 拡大字幕編集の入力直後の保存・書き出し

macOSのオフスクリーンGUIテストで、文章を編集して保存・書き出しをクリックしても、保存内容が編集前のままになる。変更前でも次の3ケースが再現した。

- `test_project_save_restart_reload_e2e_preserves_edits_and_unsaved_switch`
- `test_qml_multiline_editor_live_previews_and_saves_manual_break`
- `test_editor_render_e2e_saves_edits_and_burns_subtitles`

`MainWorkflowScreen.qml` の拡大字幕入力はフォーカスを失う際に本文をバックエンドへ反映する。保存ボタンは直接 `saveProject()` を呼ぶ。フォーカス移動に依存する確定順序が原因候補。テストは実クリックを使うが、入力自体は `setProperty("text", ...)` であるため、実キー入力およびWindows実画面での再現範囲は未確認。

次は入力確定と保存・書き出しの順序を検証する。テスト側で事前に別コントロールへフォーカスを移して成功させるだけの修正はしない。

### 2. 一時ディレクトリのパス比較がmacOSの表記差で失敗する

`/var/...` と解決後の `/private/var/...` を直接比較しているため、同じファイルでも既存ケースが失敗する。代表例は `test_changing_export_directory_preserves_editor_and_autosave_path`。次は共有GUIテストセッションの一時ルートを正規化するか、ファイル同一性を検証する比較へ整理する。画面に表示するパスの契約とは分けて扱う。

`test_output_unset_qml_offers_export_and_distinct_save_locations` はパス比較失敗後にポップアップの後処理を飛ばし、後続のショート画面検索にも失敗する。失敗時の後処理も確認する。

### 3. 字幕操作のボタン接続に検証の空白があった

削除・履歴操作にはバックエンド直接呼び出しのテストがあるが、通常編集画面のボタンから一連の結果を確認する検証が不足していた。今回、既存GUIテストモジュールに以下を追加した。

- 最後の字幕を削除 → 操作可否更新 → Undo → Redo → 保存 → 再読込
- Undo後に別の字幕を追加 → 古いRedoが無効になる
- 保存失敗 → 元ファイル・未保存編集の保持 → 同じ保存ボタンで再試行
- 再生位置が字幕の端・範囲外では分割不可 → 中央で分割 → Undo

いずれも対象ボタンを実クリックし、操作本体をモックしない。保存失敗の注入と、このケースの自動保存タイマー開始だけをモックする。再読込と再生位置設定はバックエンドAPIを利用する。
